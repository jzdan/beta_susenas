B. Langkah rinci

B1 · Menambah pengguna (PML & PCL)

Menu Admin · Data → Pengguna, bagian “Tambah pengguna”.

Klik Simpan. Berikan username + kata sandi ke petugas masing-masing. Ganti sandi lewat menu Akun.

PerhatikanGanti kata sandi akun admin bawaan sebelum dipakai produksi.

B2 · Impor master Wilkerstat (sekali)

Menu Setup awal → Impor Wilkerstat. Kabupaten adalah jenjang teratas (aplikasi ini untuk 1 kabupaten saja, tanpa jenjang provinsi). Tambah satu-per-satu lewat form Tambah/Sunting/Hapus di halaman itu, atau tempel CSV berkolom code,name,level,parent_code untuk banyak sekaligus, lalu Pratinjau → Simpan.

JenjangPanjang kodeContoh
kabupaten43526 — Bangkalan (tanpa induk)
kecamatan73526001 — Kamal … 3526018 — Klampis
desa103526001001
  • Urutkan dari atas: kabupaten → kecamatan → desa (induk harus muncul lebih dulu).
  • parent_code harus jadi awalan dari code (kosongkan untuk kabupaten).
  • Tingkat kecamatan sudah cukup untuk penugasan & filter. Desa opsional (untuk Peta Progres per desa).

B3 · Buat Siklus Survei (tiap periode)

Menu Admin · Data → Jadwal Lapangan. Isi nama (mis. “SUSENAS Maret 2026”), periode (2026-03), tanggal mulai/akhir lapangan, status persiapan.

B4 · Versi kuesioner

Menu Metadata. Kalau kuesioner tidak berubah, pakai versi yang sudah aktif. Kalau berubah (mis. KOR menambah MBG):

  1. Duplikasi versi aktif → beri kode baru (mis. VSEN26.KP).
  2. Jadikan aktif pada versi baru itu.
  3. Sunting blok/rincian/pilihan/aturan seperlunya. Ubah tanggal berlaku bila perlu.

B6 · Pembagian daerah untuk PML & PCL

Cara 1 — lewat file DSRT (paling efisien): isi kolom petugas & pml untuk tiap baris. Sekali impor, penugasan langsung beres.

Cara 2 — di aplikasi (setelah impor):

  1. Menu Daftar Sampel.
  2. Filter Kecamatan = Kamal (dan/atau Status, Petugas “belum ditugaskan”).
  3. Centang baris yang mau ditugaskan (atau centang semua).
  4. Pada “Tugaskan ke petugas…” pilih PCL, klik Tugaskan terpilih.
  5. Ulangi untuk kecamatan lain (mis. Blega).

Untuk PML: penugasan per-sampel juga mengisi kolom PML, atau pakai kolom pml di DSRT. Selain itu isi Wilayah scope PML (Pengguna → Sunting) dengan kode kecamatannya supaya seluruh tampilannya otomatis terbatas.

Batasan saat iniWilayah scope hanya menerima satu awalan kode. Jika seorang PML memegang lebih dari satu kecamatan yang tidak berurutan, kosongkan scope-nya (lihat semua) atau isi 3526 (seluruh kabupaten). Penugasan sampel per orang tetap akurat.

B7 · Harga & Kalori Komoditas

Menu Harga & Kalori Komoditas. Perbarui harga_min/harga_max/kalori per komoditas Blok IV.1 bila BPS mengeluarkan referensi harga baru untuk periode itu. Bisa edit per baris atau impor Excel/CSV.

B8 · Aturan Validasi

Menu Aturan Validasi. Aturan pemeriksaan anomali sudah termuat. Admin cukup: nyalakan/matikan aturan yang (tidak) relevan, dan ubah angka ambang bila perlu. Menyusun aturan baru ada di “Mode lanjutan” + “Kamus variabel”.

B9 · Kesehatan sistem & cadangan

  • php artisan susenas:health — pastikan “tidak ada masalah terdeteksi”.
  • Cadangan basis data berjalan otomatis (terjadwal harian). Pastikan folder cadangan aman & dicek berkala.

B10 · Aktifkan lapangan

Menu Jadwal Lapangan → ubah status siklus dari persiapan ke lapangan. PCL sekarang bisa membuka sampel & mulai entri.

Setelah lapangan selesai: ubah status ke pengolahan, lalu selesai (mengunci siklus — tidak ada perubahan data lagi).

C. Daftar periksa go-live

  • Kata sandi akun admin sudah diganti
  • Master Wilkerstat terimpor (18 kecamatan Bangkalan, pratinjau 0 error)
  • Akun semua PML & PCL dibuat; wilayah scope PML terisi
  • Siklus survei periode ini dibuat, jadwal lapangan diisi
  • Versi kuesioner yang benar berstatus “aktif”
  • Daftar sampel (DSRT) terimpor untuk siklus itu
  • Semua sampel sudah punya petugas (filter “belum ditugaskan” = kosong)
  • Harga & kalori komoditas ditinjau
  • Aturan validasi ditinjau (yang tidak relevan dimatikan)
  • susenas:health bersih
  • Status siklus diubah ke “Lapangan”
